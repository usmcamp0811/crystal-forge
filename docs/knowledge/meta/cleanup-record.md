# Knowledge cleanup record

The first migration of this bundle was lossless. It preserved every source claim
and marked doubtful claims as verification candidates. The repository owner then
authorized a **semantic cleanup**: put the current, correct guidance in the main
text, and record each correction here. This record is the only place that lists
the old claims. Operator guides and architecture pages state the current
behavior without stale notes.

## Rules for this record

- **Revision.** Every code fact is checked at Crystal Forge revision
  `3b23d36f24fbf9ba05045c43b5325fd000dbd9b2` (`origin/dev`). A fact can change
  after this revision.
- **Evidence.** A fact has a code path (and, for schema facts, a migration
  number). Age of a document and presence of code are not proof of current
  behavior.
- **History.** A superseded design stays in the bundle only with its date or
  revision and its successor. An approved design stays, and the page states the
  implementation gap.
- **Completion criterion.** A current guide MUST NOT keep a claim that is known to be false in its main text, even when a nearby note says the claim is false. A historical document is the only exception, and it carries a date and a successor.
- **No runtime change.** The cleanup changed documents only. It removed no
  runtime code, NixOS option, SQL view, or migration. Candidates for removal are
  listed in [Runtime retirement candidates](#runtime-retirement-candidates).
